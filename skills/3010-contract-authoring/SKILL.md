## Decomposition By Guarantee

The unit of a work contract is a **proof boundary**: the smallest whole behavior whose completion proof can falsify the requested outcome across every surface that co-produces it. Do not use service boundaries, files, packages, actors, CLI subcommands, review convenience, or parallelism as unit boundaries unless they are also proof boundaries.

- Name the whole behavior the bank of work must make true, then name the proof that would falsify or confirm it in the real runtime shape.
- Find the convergence points where multiple surfaces become correct only together — a shared assertion gate, shared runtime state, shared process boundary, shared route, shared DB ownership, or shared externally advertised operation is the tell of one proof boundary.
- Every surface required to run that proof belongs in the same unit, even when that makes the unit larger. Surfaces sharing no proof boundary go to separate units.
- A group of units is decided by the convergence-zone map run over the whole bank first — one unit per zone plus a final composition unit whose whole-guarantee proof exercises the assembled behavior. Never pre-decide the count.
- A verifier's precondition must be produced by a contracted deliverable inside a named predecessor unit; a precondition relying on an uncontracted side effect is invalid — block before lock.
- Block before lock when a proposed split lets each unit pass locally while the assembled behavior can only be proven after everything merges. That is over-decomposition.

Make the decomposition auditable in the contract: the proof-boundary map names the whole behavior, included surfaces, excluded surfaces, adjacent prior-unit surfaces that can be affected, and any required final composition unit.

`Claims` lists the claim ids this task collapses. When the unit spans surfaces that co-produce one guarantee, the task list ends with a whole-guarantee proof task whose `Proof Surface` exercises the assembled behavior at the shared assertion gate; "all per-surface tasks pass" is necessary but never sufficient. Every commissioned collapser application is owned by at least one task whose
deliverable executes or installs it at the declared boundary and retains its
witness. Applications are not restricted to Rust; proto, web, native, and
flat-page routes receive the same ownership.

## Post-Lock Human Change

not reopen it, create a successor contract, classify a delta, Cut a generation,

## Mandatory Fail-Closed Completion Gate

Gate id: `mandatory_fail_closed_completion_gate_v1`. A packet must carry
`fail_closed_completion_exceptions: "none"` using the schema's exact sentinel,
unless a human-authored pre-Lock entry already exists. A legacy contract must
contain the exact section:

```md
## Fail-Closed Completion Exceptions

none
```

Rules as in root policy: the section is mandatory; the normal value is `none`; actors never create, infer, populate, request, or broaden exceptions; any non-`none` entry must exist before lock, name the exact surface, exclude it from completion, and carry traceable lineage; and with `none`, any fail-closed, stubbed, placeholder, `unimplemented`, `unsupported`, `available: false`, catalog-without-handler, mock/fake/synthetic, rejection-only, or compile-only behavior in the claimed surface blocks completion.
